# Relay public adoption gaps — 2026-10-04

Read-only audit of Relay candidate `2f41d440a51268eeaae0246c840072f3ae5bdf16`, official competitor pages, and first-party GitHub metadata. No browser/device task, installation, test run, release, or public post was performed for this note. Existing implementation and historical qualification do not establish fresh usability of this candidate.

Relay already has the central product loop. The immediate gap is making a newcomer understand the reason to use it, see genuine evidence, and reach one successful task. Public views cannot establish that these gaps caused a particular impression count.

## Three fixes to prepare now

1. **Unify the reason to adopt and the first click.** Keep the accurate record/run/review loop and connect it to agent-assisted development: for example, “Record a user flow. Let your coding agent run it again. Review the screenshots.” Add prominent links to a concrete first-success guide and actual demo evidence. Align local package descriptions with the selected promise. Prepare any public repository description/homepage change for review; this audit does not authorize changing them.
2. **Use the existing real demo as the first success.** Put prerequisites, one source-checkout path, expected Member settings screenshot, seeded overlap to inspect, saved Test/Run IDs and repeat command in one linked guide. The contributor CLI can enable its existing canonical local gallery so the evidence link opens without a second UI process. Reproduce before copying a screenshot into tracked docs, retain candidate/run/browser/config metadata, and label the controlled defect as seeded. Keep the local-tarball path clearly separate until a downloadable or published artifact exists.
3. **Expose first-test help at the empty Tests state.** Add a concise link to the existing Settings → About guidance, and explain the completion criterion there: save a Test, run it again, open retained screenshots. Preserve the already-simple URL entry. This removes a discoverability gap without inventing another execution or onboarding system. A short agent prompt can request the same flow and returned IDs/evidence using the existing guides.

## Limits

This audit cannot explain a million-view difference. It has no controlled comparison of post age, audience, paid promotion, network amplification, video retention or posting cadence; it cannot infer conversion, revenue or product reliability from counters. No complete X video corpus was watched by this subtask. The useful conclusion is a prioritized adoption hypothesis: clearer promise and inspectable evidence reduce the work needed to understand and try Relay. Measure first-run completion and successful repeat after these changes before claiming improved conversion.

Existing local demo exports were inspected as historical artifacts: `.relay/first-run-demo/cbf727c8-1838-4c74-a522-d66cf062bdbe/Member settings.png` visibly shows Save overlapping the team-seat text. This note did not validate its Run manifest or rerun it; it must not be relabeled as fresh acceptance. The tracked video found in `packages/app/src/visual-fixtures/assets/report-video.webm` is a UI fixture, not launch evidence.
