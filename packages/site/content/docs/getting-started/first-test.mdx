---
title: Your first test
description: Write or record one flow in your own website, run it again, and review what Relay saw.
---

Your first Test is one short journey in your own website: something you check by hand today, like adding an item to a cart and reaching checkout. Write it as YAML or record it once, and Relay can repeat it whenever you want. Recording is the fastest way to make the replay exact without a model key.

Relay runs locally. The npx path is the easiest start; the source checkout is the contributor path.

## 1. Get Relay running

Install [Node.js 24 or newer](https://nodejs.org/en/download) and Chrome, Chromium, or Edge. Then:

```bash title="Terminal"
npx -y @relay/cli
```

Follow the CLI output to open the local workspace. For the contributor source build, use the [installation guide](/docs/getting-started/installation). For an unusual browser installation, set `RELAY_BROWSER_EXECUTABLE` to its absolute path before starting the service.

## 2. Record one flow

In Relay, choose **New test**, pick **Website**, and enter your site's address (a local one like `localhost:3000` works). Relay opens a fresh browser.

Click through the journey the way you normally would. Each action becomes a step. Add a **check** where something must be true, like "the order total is visible", and a **screenshot** where you want to look at the screen later. When you're done, choose **Stop and review**, then **Save**.

No account, model key, Android tools, or iOS tools are needed for recorded steps.

## 3. Run it again

Open the test and press **Run**. Relay repeats every step in a fresh browser and shows each one with its timing and the screen it reached. If a check fails, it says what it **expected** and what it **saw**, next to the screenshot.

A passing check is not the same as someone approving how the screen looks. That is a [screenshot review](/docs/workflows/review) decision.

## 4. Repeat it anywhere

The same saved test runs from the command line and from coding agents:

```bash
npx -y @relay/cli run "Checkout" --device browser
```

Next, [record more journeys](/docs/workflows/recording) or learn how [runs work](/docs/workflows/running). If you write plain-English steps instead of recording exact interactions, [saved paths](/docs/workflows/saved-paths) explain how successful resolutions are replayed and refreshed. Aim for a single repeatable outcome before adding more coverage.
