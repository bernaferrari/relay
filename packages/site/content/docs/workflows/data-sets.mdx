---
title: Data sets and Plans
description: Run the same journey with selected prompts, languages, devices, or accounts.
---

A **Test** describes one journey. A **Plan** groups Tests and the configurations to repeat. A **Data set** supplies approved values such as prompts or languages.

## Start with a working Test

[Record and replay](/docs/workflows/recording) one short flow on one target. Add a useful [outcome check](/docs/workflows/waits) and a named screenshot before multiplying the cases.

## Parameterize an input

Use a named Run input such as `{{chat_prompt}}` in the recorded text action. Save and approve non-sensitive values in the Project Data sets, then bind that input to the intended action when adding the Data set to the Plan.

Keep the display label and actual value separate:

| Row label   | Text sent to the app                    |
| ----------- | --------------------------------------- |
| Tides       | Explain ocean tides in three sentences. |
| Paper plane | Suggest one paper airplane tip.         |

“Tides” is a useful review label, not the prompt itself. Changing a row label must not silently change the text sent to the app.

## Create a Plan in the UI

1. Open **Tests**, choose **New plan**, and name it.
2. Choose the App and the Tests to include.
3. Under **Repeat with data**, choose the Data sets and exact rows you want.
4. Save the Plan, select its browser or devices and account setup, and inspect the case count.
5. Run a pilot and inspect its result before continuing with more cases.

Each Test consumes only the inputs it references. An unrelated input can still create additional cases even when it does not change that Test's actions. Remove dimensions you do not need.

## Choose the combinations

| Strategy                       | Example with two prompts and two languages                                                           |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- |
| All combinations (`cartesian`) | Both prompts in both languages: four combinations.                                                   |
| Pair in order (`zip`)          | First prompt with first language, second with second: two combinations. Lists must have equal sizes. |

With three Tests, four combinations can mean twelve executions. Check the preview before starting a large language or device sweep.

Language is a setup change, not just a label on a case. Use an App locale dimension or a qualified recorded language-change path, then verify the actual app language. A prompt Data set does not automatically translate the app.

## Inspect the saved Plan from the CLI

```bash
pnpm relay plan list <app-id> --json
pnpm relay plan get <app-id> <plan-id> --json
pnpm relay plan preflight <app-id> <plan-id> --json
```

Replace the placeholders with saved IDs. List and get read selections; preflight checks cases and bindings without sending device input. A successful preflight is not a successful Run.

`pnpm relay plan --help` shows execution options. One case is the default for CLI `plan run`; `--all` requests all selected cases. Use explicit device bindings or a saved browser lane, rather than assuming the target from a different Run.

## Review and repeat

Inspect the Plan's Gallery to compare its named screenshots across cases. Check captured, blocked, missing, and pending-review counts, not just the number of files in a folder.

Once a repetition starts, resuming it keeps the selected input values from that attempt, even if the Data set changes later. Test changed values in a new repetition.

Once the intended cases work, [schedule the Plan](/docs/workflows/scheduling). First make sure the target can reach the same starting screen on every repetition.
